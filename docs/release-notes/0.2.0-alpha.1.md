# Pitstop 0.2.0-alpha.1

This is the first Windows alpha candidate for Pitstop's modules-first C++ workflow. See the [release-readiness report](../architecture/alpha-readiness.md) for the validation status before distributing these packages.

## Highlights

- Open trusted Xmake projects and inspect evaluated targets, source membership, dependencies and configurations.
- Browse named modules and partitions, navigate to providers, inspect dependencies and potential consumers, and complete import names in context.
- Edit C++ with clangd completion, diagnostics, hover, navigation and references. Saving a module interface can refresh semantic information while preserving unsaved buffers.
- Build, rebuild, clean and run executable targets through Xmake. Native build diagnostics, process output, arguments, environment, working directory and interactive input are available in the IDE.
- Create module sources with the New C++ Module dialog and query the same module snapshot over MCP.

## Installation and upgrades

Use Windows x64 with Xmake and Xrepo 3.1.2 and LLVM-MinGW 23.1.6 with libc++, clangd and clang-scan-deps. C++23 and C++26 were exercised on this profile. Install the toolchain separately and follow the [Windows setup and quick start](../../README.md#windows-setup).

The candidate installer, `Pitstop-windows-x64.exe`, installs per user. For a portable copy, extract `Pitstop-windows-x64-portable.zip` and run `Pitstop/Pitstop.exe`. A `pitstop-data` directory beside the executable stores state with the portable build. The candidate packages are unsigned. Automatic updates are disabled. To upgrade manually, close Pitstop and use the newer installer, or extract the newer portable package into a fresh folder and move your `pitstop-data` there. Installed state remains in `%LOCALAPPDATA%\Pitstop`.

## Validation and limitations

The [Hello Modules example](../../examples/hello-modules) built and printed `Hello, modules!` with the reference profile. The validation recorded 618 passing unit tests and 10 passing native reference tests. Cold compilation database exports timed out for the synthetic 500- and 1,000-module workspaces. See the [release-readiness report](../architecture/alpha-readiness.md) for the full suite status, MCP coverage and performance measurements.

Native debugging and the Xrepo package installation UI remain future work. Unsaved cross-module semantic propagation and other native toolchain profiles remain unverified. The dependency index can report incomplete results. Compiler scanning does not confirm every re-export or implementation-unit relationship. The potential-impact view describes dependency reachability.
